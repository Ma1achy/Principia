# Code reviewer — checklist

Named on every task (`plan/WORKFLOW.md` § "Task files": `code` and `qa` always). This checklist holds the corpus's structural
rules: what is compiled where, what may cross which boundary, what is generated, what is baked, and how the docs change.
Crate names are the plan's layout (`plan/WORKFLOW.md` § "Conventions: crates and runners (R-146)").

## 1. One source, compiled twice

- [ ] Physics (decode, canonicalise, wrapper, occupants, detectors, events) lives once in `crates/kernel`, generic over the float type, compiled to f32 SPIR-V → WGSL by rust-gpu and to f64 by rustc; there is no CPU-only or GPU-only copy of any physics logic. `docs/contracts/principia_canonical_spec.md` § "1. The substrate (the defining decision)"; `docs/design/principia_core_design.md` § "1. Physics defined once, compiled twice — now *structurally*, not by discipline"
- [ ] No `#[cfg]` or type-dependent branch makes the f32 and f64 instantiations run different logic; a tolerance that must scale with precision sits where the value is used, never where a branch is taken. `docs/contracts/principia_integrator_contract.md` § "Rules the new kernel must hold by construction"; `docs/contracts/principia_parity_contract.md` § "Tier L — exact, no tolerance (the bulk of the suite)"
- [ ] The kernel takes the chart description as a uniform and does map → z → decode → `(m, r, p)` → integrate in-kernel; there is no pre-decoded IC buffer. `docs/design/principia_core_design.md` § "3. Kernel eats chart params, decodes in-kernel"
- [ ] Charts and occupants are type parameters the compiler specialises; there is no runtime axis-kind, link, occupant or slot interpreter on the GPU. `docs/contracts/principia_lowering_contract.md` § "Part 1 — What lowering is"; `docs/contracts/principia_chart_decoder_contract.md` § "Design axioms (the six that must survive contact with a code agent)"
- [ ] Compute occupants (steppers, regularisations, protocols such as reversibility's forward + reverse) are build-time Rust variants only; nothing compiles user Rust or compute source at runtime. `docs/contracts/principia_canonical_spec.md` § "1. The substrate (the defining decision)"; `docs/contracts/principia_lowering_contract.md` § "Part 4 — The precompile rule"; `docs/contracts/principia_gui_state_contract.md` § "3. The registry is the scanned filesystem — for the *fragment* side; compute occupants are Rust build variants"
- [ ] The fragment side is hand-written WGSL assembled from keyed snippets (prelude, one function per node, generated `shade()`), hot-reloaded with async compile and last-valid fallback. `docs/contracts/principia_lowering_contract.md` § "Part 2 — Two assembly mechanisms (the substrate split; the old "one mechanism" claim retires)"
- [ ] Compute and fragment meet only at the payload buffer (`SimState` / `ICDescriptor`). `docs/design/principia_systems_architecture.md` § "5. The seam catalogue"; `docs/contracts/principia_lowering_contract.md` § "Part 1 — What lowering is"
- [ ] The build respects the dependency DAG: layout table and link registry are roots; the decoder precedes the kernel; canonicalise precedes the integrator. `docs/design/principia_systems_architecture.md` § "7. Hierarchy and dependency (the build DAG, abstract)"

## 2. GPU compile discipline (the determinism note)

- [ ] Branch conditions compare against compile-time constants, integer counters or single-rounded arithmetic only; no runtime `pow` / `sqrt` / `div` decides control flow. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"; `docs/contracts/principia_integrator_contract.md` § "Rules the new kernel must hold by construction"
- [ ] The `N_sub` lookup is a generated comparison tree over 64 frozen f32 constants (generated with f64 libm at build time) — no runtime sqrt/div/pow, loop or dynamic index. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"; `docs/design/principia_dd_integrator.md` § "3.3 Substep law — and the determinism pin, made concrete"
- [ ] Every multi-op branch input (`d²`, `|Δn̂|`, `E_rel`, and any other the task adds) is written with an explicit `fma` in a fixed form, and the list of such inputs is enumerated in the code or docs. `decisions.md` § "R-34 — FMA: explicit fma at every branch input, enumerated *(IE-6)*"; `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"
- [ ] Every float → int cast is preceded by a clamp in f32 into the target range. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"
- [ ] No non-finite literal (`f32::INFINITY`, `T::infinity()`) appears; min/max folds seed from the first element. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"; `docs/contracts/principia_integrator_contract.md` § "Rules the new kernel must hold by construction"
- [ ] Loops are `while` with the terminal flag in the condition and zero `break`s; no counted `for` with a mid-body exit. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"; `docs/contracts/principia_integrator_contract.md` § "Part 1 — The shape: a swappable `step()` slot inside a fixed wrapper"
- [ ] Indices in the kernel are constant or unrolled wherever the count is small, so no implicit bounds check injects a multi-level exit. `docs/notes/principia_gpu_determinism_note.md` § "The discipline (each rule = one measured failure)"
- [ ] Every march loop has a bound (no bare `loop {`). `docs/contracts/principia_integrator_contract.md` § "Rules the new kernel must hold by construction"
- [ ] No allocation (`Vec`, `Box`, `dyn`, `std`) in the kernel hot path. `docs/contracts/principia_integrator_contract.md` § "Rules the new kernel must hold by construction"
- [ ] The driver layer is written fresh to these rules; only the step / deriv / Hamiltonian physics layer is ported from prin-rs. `docs/contracts/principia_integrator_contract.md` § "The split"

## 3. Baked vs uniform (lowering)

- [ ] Compute side: chart type, link selection, integrator occupant and tier co-computations (the FTLE shadow) are baked variants; wrapper config, chart params and per-quad `c, h, x₀, J_D, T` are uniforms; decode mode is a per-quad uniform flag. `docs/contracts/principia_lowering_contract.md` § "Compute side"
- [ ] The ensemble copy is not a baked variant: `copy_index` is a uniform and each copy is the same kernel dispatched again. `decisions.md` § "R-102 — The ensemble isn't a baked variant *(closes RQ-62)*"; `docs/contracts/principia_lowering_contract.md` § "Compute side"
- [ ] The kernel's one debug mode (the bring-up mode) is a baked, pre-built variant, not `DEBUG_MODE` flag bits; `QuadRequest.flags` bits 6–7 stay reserved. `decisions.md` § "R-41 — `DEBUG_MODE` uses the baked variants, not flag bits *(RS-1 (b))*"; `decisions.md` § "R-75 — The kernel keeps one debug mode *(closes RQ-26)*"; `docs/contracts/principia_scheduler_contract.md` § "`QuadRequest.flags`"
- [ ] Fragment side: the stain graph (node occupants + wiring) is the baked fragment key; debug field views are generated one tiny source per field on demand, never a mega-switch; slot uniforms and view-only display state are uniforms; compositor shaders are fixed and precompiled. `docs/contracts/principia_lowering_contract.md` § "Fragment side"
- [ ] Navigation (tilt, pan, slice, zoom, lock) and the playhead are uniform writes only; no gesture reaches a compiler. `docs/contracts/principia_lowering_contract.md` § "Part 4 — The precompile rule"; `docs/contracts/principia_lowering_contract.md` § "Compute side"
- [ ] The read-side `SimState` type is fixed across variants with plain field syntax; a tier-absent derived field reads NaN; `const has_<feature>` is baked alongside; validity uses descriptor predicates (`sd_is_failed`, `ftle_valid`), never `isnan()`. `docs/contracts/principia_lowering_contract.md` § "Part 3a — The uniform read-side interface (tier features degrade by NaN, not by struct shape)"; `docs/contracts/principia_canonical_spec.md` § "9. The load-bearing invariants (the walls — the primary comparison checklist)"
- [ ] Storage never holds NaN: a blown-up sample stores its defined failed-state values; sentinels (e.g. `diffusion = −1.0`) are stored bit-exact. `decisions.md` § "R-79 — NaN and sentinels *(closes RQ-30)*"; `docs/contracts/principia_render_contract.md` § "Part 4 — Semantic rules"
- [ ] Built-in fragment occupants use the same read-side interface and compile path as custom ones. `docs/contracts/principia_lowering_contract.md` § "Part 3a — The uniform read-side interface (tier features degrade by NaN, not by struct shape)"

## 4. Generated code from the ledger

- [ ] Pack/unpack (Rust for kernel and host, WGSL for the fragment side), the export decoder, the debug catalogue and link functions are generated from the one ledger in `crates/ledger`; no layout, offset or link inverse is hand-duplicated anywhere. `docs/design/principia_dd_generation_root.md` § "1. What it is"; `docs/design/principia_systems_architecture.md` § "5. The seam catalogue"
- [ ] No generated file is hand-edited; the generated-file guard detects edits; changes go through the ledger and the generator. `docs/design/principia_dd_generation_root.md` § "4. Seams (obligations → integration tests)"
- [ ] Every ledger entry carries the full metadata schema; a field without a complete entry fails generation loudly with the field named. `docs/design/principia_dd_generation_root.md` § "3.8 Metadata schema (what every entry must carry)"
- [ ] The schema version is the content hash of the canonicalised ledger (the continuation table included), never a hand-bumped integer, and it is in the payload compatibility signature. `decisions.md` § "R-36 — Schema version = content hash of the ledger *(PL-1)*"; `decisions.md` § "R-63 — The continuation table is hashed with the ledger *(confirms R-36's application)*"
- [ ] Reserved bits stay reserved; any new use is a ledger edit (and so a schema change). `docs/design/principia_dd_generation_root.md` § "6. Deferred / flagged"
- [ ] WGSL bit-field accessors use the u32 `extractBits` overload, never the sign-extending i32 one. `docs/design/principia_debug_tooling_plan.md` § "B. Payload field views — `sample_descriptor` (bit-packed u32)"; `docs/design/principia_dd_generation_root.md` § "5. Tests (properties any generator must satisfy)"
- [ ] The logical `RenderSample` view is accessor functions over the physical structs; no pass materialises an unpacked copy of the payload. `docs/contracts/principia_render_contract.md` § "Part 1 — The payload (render input)"
- [ ] Payload accessors use one name each (the payload §6 names), with `tm_t_dmin` and `fgw_length_raw` in the unpack layer. `decisions.md` § "R-86 — The payload doc governs the eight payload items *(closes RQ-37)*"

## 5. The firewall and the two membranes, by crate graph

- [ ] `crates/engine` marks only the typed state surface `pub` (`SimConfig`, `RenderState`, `ViewUI`, `SetField`, the snapshot); scheduler, cache, kernel and payload buffers are crate-private. `docs/contracts/principia_gui_state_contract.md` § "1. The one-way dependency rule"; `docs/contracts/principia_canonical_spec.md` § "1. The substrate (the defining decision)"
- [ ] `crates/gui` depends on the state surface only; neither `crates/engine` nor `crates/kernel` depends on `crates/gui`. `docs/contracts/principia_gui_state_contract.md` § "1. The one-way dependency rule"
- [ ] No GUI code holds a `&mut` into engine state or a live handle to an engine struct; the TS side (M8) holds no wasm handles. `docs/contracts/principia_gui_state_contract.md` § "1. The one-way dependency rule"; `docs/design/principia_systems_architecture.md` § "3. The membrane — the deployment view (demoted, not diminished)"
- [ ] GPU↔CPU crossings are only the five catalogued (dispatch uniforms, render config, bake, `QuadReduction`, sanctioned pulls); `QuadReduction` is the sole automatic return. `docs/design/principia_systems_architecture.md` § "3. The membrane — the deployment view (demoted, not diminished)"; `docs/design/principia_systems_architecture.md` § "The return paths"
- [ ] wasm↔JS crossings are only `set_field` edits, the GUI-sized snapshot (~10 Hz) and the one-time canvas transfer. `docs/design/principia_systems_architecture.md` § "3. The membrane — the deployment view (demoted, not diminished)"; `decisions.md` § "R-94 — The GUI snapshot is ~10 Hz *(closes RQ-45)*"
- [ ] No per-sample payload, quad tree or reduction array crosses either membrane; only summaries. `docs/contracts/principia_canonical_spec.md` § "6. Memory & deployment model *(authoritative: `memory_tiers`, `caching_contract`, `deep_zoom`, `systems_architecture`)*"; `docs/design/principia_systems_architecture.md` § "6. Cross-cutting invariants (the load-bearing walls)"
- [ ] The scheduler never seeds an IC from a neighbour's or parent's state, never stands a neighbour's `SimState` in for an unfinished quad, and puts no scheduler state into the payload or its signature. `docs/contracts/principia_scheduler_contract.md` § "Part 1 — The firewall: the scheduler is arbitrary about *what* it looks at, never about *what* it sees"
- [ ] Nothing reads the blurred backdrop or the SSAA-resolved colour as data. `docs/contracts/principia_caching_contract.md` § "Part 5 — The stale backdrop: blur means loading"; `docs/notes/principia_sampling_msaa_note.md` § "The two firewalls (unchanged, restated for this model)"

## 6. Keys and caching

- [ ] Sim key vs render key follow the blast-radius table: render-mode, palette, overlays → nothing; `T`, `dt_macro`, thresholds, occupant, links, chart/decode version → all sim buffers; `render_scale`, lock-to-native, `MAX_REL_DEPTH`, frame budget, transport → nothing. `docs/contracts/principia_caching_contract.md` § "Part 2 — What invalidates what (the dependency graph)"
- [ ] Depth and `E` are not on the sim key: copies are cached per `copy_index`, the nominal's key excludes `E`. `decisions.md` § "R-89 — Depth and E are not on the sim key *(closes RQ-40)*"
- [ ] The sim key holds the slice plane (`z₀`'s out-of-plane part, span{q₁, q₂}, in-plane orientation); in-plane pan and zoom re-address; slice-out, tilt and rotate re-integrate; lock changes neither key. `decisions.md` § "R-92 — What the sim key holds of navigation *(closes RQ-43)*"
- [ ] Quad addresses are `(level, i, j)` in the slice plane's own frame, relative to the plane anchor. `decisions.md` § "R-97 — Quad addresses live in the slice plane *(closes RQ-57)*"
- [ ] Cache lookup is identity (chart + params, slice plane, `QuadID`) and compatibility signature; the word buffer shares identity, signature and `t` with its `SimState` and evicts with it. `docs/contracts/principia_caching_contract.md` § "Part 1 — Two-level keying: identity vs validity"
- [ ] Preview and refined payloads are distinct cache entries; a preview payload is never served where full quality was asked, nor read by a quantitative export. `docs/contracts/principia_scheduler_contract.md` § "Part 5 — Preview vs refine is a second sim key"

## 7. Vocabulary and scope

- [ ] No retired term reappears (`TileID`, `computeTile`, `samples_per_tile`, the `M` checkpoint count, a `TIMEOUT` state, `sd_is_untrusted`, "N ensemble shadows", the `Math.fround` `N_sub` rule, a TS layout constant generating WGSL). `docs/contracts/principia_canonical_spec.md` § "8. Locked vocabulary"
- [ ] Code uses the locked taxonomy: QUAD, SAMPLE (N×N, `SAMPLES_PER_QUAD_AXIS`), TILE (a sample's screen footprint), PIXEL, `QuadReduction`; no `TILE_PIXEL_RES` and no sample→pixel interpolation. `docs/design/principia_memory_tiers.md` § "1. Taxonomy (locked vocabulary)"
- [ ] Nothing is implemented from an archived file except the parts the index says still stand. `docs/read_first/principia_INDEX.md` § "Archived — record only, do not implement"
- [ ] No parked post-1.0 item is built or half-started. `docs/read_first/principia_00_philosophy.md` § "7.7 The rule for this section"
- [ ] No per-pair view ships before `dominant_pair` is specified. `decisions.md` § "R-38 — Per-pair views are out of v1 until `dominant_pair` is specified *(PL-3)*"
- [ ] No IC-keyed cross-chart cache sharing in v1. `docs/contracts/principia_caching_contract.md` § "Part 3 — Cross-chart sharing: permitted, deferred"
- [ ] Every settled default constant in the diff cites where it was measured, or is a calibration requirement's value. `docs/contracts/principia_canonical_spec.md` § "Principia — canonical architecture & design (the yardstick)"; `decisions.md` § "R-71 — A missing value becomes a calibration requirement *(closes RQ-46 to RQ-55, values)*"

## 8. Docs first, and the porting rule

- [ ] The PR changes no design decision in code alone: a design change is in `docs/` first, with a REVIEW_QUEUE entry and a ruling, then the plan, then the code. `decisions.md` § "Porting rule — a port adds, it never removes a decision"; `plan/MILESTONES.md` § "Assumptions"; `plan/WORKFLOW.md` § "Escalation"
- [ ] Where two docs conflict, the code follows the later consolidated doc (payload doc, colour_composition, parity_contract, refinement policy) and the conflict is reported, not silently chosen. `decisions.md` § "R-70 — Where two docs conflict, the later consolidated doc wins"; `decisions.md` § "R-1 — The markdown corpus is the only authority"
- [ ] A doc change adds and never removes or alters a decision without an RQ and a ruling. `decisions.md` § "Porting rule — a port adds, it never removes a decision"
- [ ] Every commit that touches `docs/`, `decisions.md` or `plan/` ends with its "Removed lines" note: each removed line is "reworded, kept at <file:line>" or "stale value, replaced by <ruling>". `decisions.md` § "Porting rule — a port adds, it never removes a decision"; `plan/WORKFLOW.md` § "Keeping the plan true"
- [ ] An edit to `GUI_DESIGN_NOTES.md` is only where a ruling contradicts it and is marked "conformed to R-n". `decisions.md` § "R-107 — Apply the RQ-67 follow-ups; GUI_DESIGN_NOTES may be conformed *(closes RQ-67)*"
- [ ] `plan/requirements.yaml` ids are never renumbered; a requirement leaves a gate only as `retired: <ruling>`. `plan/WORKFLOW.md` § "Keeping the plan true"; `plan/WORKFLOW.md` § "No deferral"
- [ ] The PR contains only its task; a task grown past one reviewable PR (~500 lines) was split in the plan first. `plan/WORKFLOW.md` § "The unit: one task, one branch, one PR"
