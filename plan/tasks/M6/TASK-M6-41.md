# TASK-M6-41 — Focus and keyboard navigation apart: a mouse-opened window takes the focus with no ring; any click or drag hides the ring and the next key press shows it (R-460, R-464)

## Goal
On the mock engine, opening the console, the Chart builder, the Profiler or any window with the mouse turns keyboard navigation on. The cause, read from the code at `ab87a879` for this task to confirm by reproduction: there is no keyboard-navigation-off state; the ring is drawn whenever the focus path is set (`crates/gui/src/app.rs` lines 920 to 930, `draw_ring`), and `Keyboard::open_window` (`crates/gui/src/keyboard/mod.rs` line 434) moves the path into every window however it was opened; a mouse-opened menu does the same (lines 382 to 385). R-450 A3 is not the cause; it is built on PR #234. This task adds the GUI's own keyboard-navigation flag beside the focus (R-460): it starts only on keyboard input (Tab, Shift+Tab, the arrows; Enter only reveals the ring), a mouse open takes the focus with no ring, and the ring and the breadcrumb's path are drawn only while it is on. It fixes the one mechanism, not each window. R-464 (closing RQ-367) adds the ring-visibility rule on the same flag: any mouse click or drag hides the ring, the focus moving exactly as R-450 A3 and R-456 say (a click on a text input still starts typing), and the next key press, whichever key, shows it again where the focus is; this task is the follow-up R-464 names, #234 merging as it stands.
