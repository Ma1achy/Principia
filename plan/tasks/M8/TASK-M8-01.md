## Goal
The GUI-facing surface already exists in `crates/engine/src/contract`, built by R-390's track and the tasks that added its fields as they needed them (R-133): the interface the GUI calls (`interface.rs`, `EngineInterface`: `set_field`, `snapshot`, `undo`, `redo`), the typed edit (`set_field.rs`, `SetField { edit, no_history }`), the snapshot (`snapshot.rs`), the three structs (`sim_config.rs`, `render_state.rs`, `view_ui.rs`), the one canonical serialisation, JCS (`canonical.rs`; R-309, R-318), the real engine's state store (`store.rs`) and the conformance suite both engines pass (`conformance.rs`). This task completes that surface and redefines none of it (R-627): every field gui_state_contract §2 lists lives in the struct §2 names, the groups still empty filled from the contracts that own them (SimConfig on the sim key, RenderState on the render key, ViewUI pure UI); SimConfig + RenderState, in the canonical serialisation, are the provenance object, so two clients edit one schema; ViewUI is defined but the engine never reads it; and the snapshot carries only GUI-sized state (view state, tier, a few scalars, the reported events), its serialised size bounded. This is the surface every later M8 task writes through.

## Deliverables
- `crates/engine/src/contract/{sim_config,render_state,view_ui}.rs` — the existing structs, their §2 field lists as amended by R-96, R-101 and R-106 completed: the groups still empty (`Chart`, `Slice`, `Links`, `Integrator`, `Collision`, `Quality`, `Palette`) and `Horizon`'s `dt`, thresholds and `eps` filled from the contracts that own them, each field taking its owning task's type where that task has merged (the quality settings TASK-M6-22's, the integrator's parameters TASK-M3-06's); the link ids are the chart registry's link-function ids; playback transport (play / pause / speed / loop), the linked views, the kept orbits and `t_cursor` are ViewUI fields. A field already there (the plane, the lock, the horizon `T`, the overlays, the playhead, the hover, the stain graph; the transport, the focus, the windows, the kept orbits, the mode) is kept as it is.
- `crates/engine/src/contract/set_field.rs` — the existing `SetField { edit, no_history }` over plain data: a `SimField` or `RenderField` path for each field added here; `no_history` is the history mark TASK-M8-03 uses (R-101).
- `crates/engine/src/contract/snapshot.rs` — the existing `Snapshot`: its `Tier` given its fields as gui_state_contract §1 and §6 name them, unless TASK-M6-22 has given them first; the DECODE_SWITCHOVER / AT_F32_FLOOR events (`Precision`, REQ-GUI-010) as TASK-M6-21 feeds them. No payload, quadtree or reduction type is reachable from it.
- The provenance object in `crates/engine/src/contract/canonical.rs`: SimConfig + RenderState written and read back in the one canonical serialisation (JCS; R-309, R-318), no second serialisation beside it.
- `crates/engine/src/contract/store.rs` and `conformance.rs` — each new path written by `store::write`, which the mock shares, and covered by a conformance case, so both engines run it (R-390).
- `crates/engine/src/state_surface.rs` — the engine's `pub` re-export of this surface; the engine applies SetFields to SimConfig / RenderState and has no ViewUI parameter anywhere.
- Tests: `schema_fields`, `provenance_roundtrip`, `two_clients`, `snapshot_bound`.
- `crates/engine/src/contract/view_ui.rs:2`, the module doc comment: "a polished GUI may define its own" reworded to "a replacement GUI, if there ever is one (v2 web's, R-571), may define its own", following gui_state_contract §2 (R-571; gui re-check 5608472158 of PR #282, applied per R-369).

## Acceptance tests
- `cargo test -p engine schema_fields` — schema test: each listed field lives in the named struct; playback transport and the linked views are ViewUI fields and are absent from SimConfig; SimConfig's link ids are the chart registry's link-function ids (REQ-GUI-036).
- Review checklist (code reviewer), with `cargo test -p engine no_viewui_reads` (a grep test over `crates/engine/src`) — no engine-crate code references ViewUI fields (REQ-GUI-037).
- `cargo test -p engine provenance_roundtrip` and `cargo test -p engine two_clients` — serialise SimConfig + RenderState in the canonical serialisation, deserialise, compare; two clients on one `StateStore`: a second client's edit is visible in the first's snapshot (REQ-GUI-039).
- `cargo test -p engine snapshot_bound` — the snapshot type contains no payload / quadtree / reduction types, and its serialised size stays below a fixed small bound at any zoom depth (REQ-PERF-071).
- Proposal: the snapshot's serialised-size bound, with sizes measured on the real engine's `StateStore` and on the mock across zoom depths (navigation `SetField`s) and every tier; the human confirms it at the M8 gate (REQ-PERF-091).
