# TASK-M8-82 — The uploaded picture: ingest in the app's own code, the SHA-256 `PictureRef` in tier 2, the content-addressed store, the `prPc` chunk, and a visible "Picture missing", never a substitute (R-585)

- **Milestone:** M8
- **Closes:** REQ-COL-160, REQ-COL-161, REQ-TOOL-208, REQ-TOOL-209, REQ-TOOL-210, REQ-GUI-391, REQ-GUI-392
- **Depends on:** TASK-M8-33, TASK-M8-53, TASK-M8-74, TASK-M7-49, TASK-M7-51
- **Needs (earlier milestones):** REQ-COL-130, REQ-GUI-340, REQ-TOOL-180
- **Reviewers:** code, qa, gui
- **Pitfalls:** none
- **Size:** ~650 lines, the tests included

## Goal
"Your image…" ingests a PNG or JPEG in the app's own code (the profile to 8-bit sRGB, alpha over the canvas background, exact area averaging to 256², stretched), its texels canonical; `RenderState` holds a SHA-256 `PictureRef`, tier 2; a content-addressed store keeps the texels while anything refers to them; every exported PNG carries them in a private `prPc` chunk, checked on read; a picture found nowhere draws `#141418` with its layers and a "Picture missing" badge, and Locate picture… accepts only a file that hashes to it (R-585).

## Deliverables
- The ingest (decode, profile conversion, alpha, the integer area average) in `crates/render/src/picture/`, its limits REQ-COL-160's proposed values.
- `PictureRef` and its hash, its tier 2 entry in `tiers.rs`; the store in the app's data folder and its collection; the `prPc` writer and reader; `picture.png` in a result folder.
- The "Your image…" dialog's preview; the missing base, the header-strip badge, the report line and Locate picture….
- Tests: `picture_ingest`, `picture_ref_tier`, `picture_store`, `picture_chunk`, `picture_missing`, `picture_upload_dialog`; screenshot case `picture_upload`.

## Acceptance tests
- Calibration: the PR proposes the two limits with their evidence (the ingest's peak memory and time at each limit on the reference machine, and the decoders' own limits); a reviewer checks them; the human confirms them at the M8 gate (REQ-COL-160).
- `cargo test -p render picture_ingest` — a fixture PNG, a JPEG and a PNG with alpha ingest to texels whose SHA-256 equals the checked-in hash on every CI platform; the PNG fixtures' expected texels and hash are computed by a stand-alone script checked in beside them (Python's standard library only: zlib to decode, the integer formula in exact fractions, hashlib's SHA-256), sharing no code with the crate, and the JPEG's checked-in hash proves only that every CI platform agrees; a 3 × 2 source with known values gives the texels the integer formula gives; a 512 × 256 source whose horizontally adjacent pixel pairs hold 0 and 1, and 2 and 3, in every channel gives texels 0 and 2 (ties rounded half to even); a one-pixel change in the source changes the hash; a 600 × 300 source fills the whole square, stretched; a fixture with an embedded profile records its conversion; a file over each limit is refused with a reason naming it and nothing is stored (controls: round half up, which gives 1 and 3, the platform's or a floating-point resampler, a fit with bars, a silent downscale of an over-limit file, and a hash that skips the texels, each fail) (REQ-COL-161).
- `cargo test -p engine picture_ref_tier` — the hash of a fixture's texels equals the checked-in digest computed from the stated bytes; PictureRef is assigned tier 2 in tiers.rs and the table stays exhaustive; an image squeezed to tier 1 reports the picture as dropped; two RenderStates differing only in the hash have different render keys; the hash is written as 64 lowercase hex digits, in the reference and in the store's path (controls: the texels in RenderState, the reference in tier 1 or none, a silent drop, and an uppercase digest, each fail) (REQ-TOOL-208).
- `cargo test -p gui picture_store` — an upload writes pictures/<hash>.png and then one SetField whose value holds only the reference, one undo entry; undo restores the previous reference and the stored file stays; a collection with the entry still in the history keeps it, and collects it once nothing refers to it; an entry referred to only by a saved view, and one referred to only by a result folder, is kept, and collected once that view or result is deleted; a stored file altered by one byte is not used and reads as missing (controls: texels in the history, a referenced entry collected, an entry collected while only a saved view refers to it, one collected while only a result refers to it, and an unverified read, each fail) (REQ-TOOL-209).
- `cargo test -p render picture_chunk` — an exported PNG of a view with an uploaded picture, reopened with an empty store, renders the picture bitwise and writes it to the store; the chunk type is prPc, ancillary and private, and for a fixture picture its data is 196,640 bytes, the reference's 32 raw hash bytes then the 196,608 texel bytes row by row from row 0, uncompressed, equal to checked-in expected bytes written by a stand-alone script that shares no code with the crate; a prPc with one texel byte changed reads state present, corrupt and draws as missing; a result folder of that view holds picture.png with the texels (controls: a PNG without the chunk, a reader that ignores it, one that uses it unverified, a zlib-compressed chunk, and a hash written as hex, each fail) (REQ-TOOL-210).
- `cargo test -p gui picture_missing` — a share link of a view with an uploaded picture opened with an empty store restores SimConfig and RenderState bitwise, draws #141418 where the picture was with the layers over it, shows the badge with the name and the hash's first 8 hex digits in the header strip, outside the plot, and lists it in the report; Locate picture… with a different image is refused naming both hashes, and with the original file restores the picture; Locate picture… is reached from the keyboard in the import report, after the missing picture's line, Enter opening it, and Tab and the arrows never land on the header strip's badge (controls: a Locate picture… the keyboard cannot reach, one not after its picture's line, a badge the keyboard lands on, a built-in drawn instead, the hatch, a restore that aborts, a Locate that accepts any file, and a badge drawn over the plot, each fail) (REQ-GUI-391).
- `cargo test -p gui picture_upload_dialog` and `cargo xtask screenshot picture_upload` — with a 600 × 300 fixture the dialog's preview is the ingested 256 × 256 texels, drawn in a square rect with no bars, before anything is applied; no SetField is sent until Apply, and Apply is offered only once the preview is shown; Cancel sends no SetField and leaves RenderState unchanged; an over-limit file is refused in the dialog with the limit named and no SetField sent; from the keyboard the dialog's sections are the preview, Apply (an element only once the preview is shown) and Cancel, Enter on Apply sending the SetField and Esc in navigation mode acting as Cancel, sending none (controls: an Apply or a Cancel the keyboard cannot reach, an Esc that sends a SetField, a preview with bars, a preview that is not the ingested texels, an Apply offered before the preview, and a Cancel that sends a SetField, each fail); picture_upload: the dialog's layout only (R-68) (REQ-GUI-392).
