# TASK-M7-66 — Print graph field inputs: the `field` node, the stain's window, absent fields, and the four "Driven by the data" presets on their real fields (R-526, R-536, R-557) ⚑

- **Milestone:** M7
- **Closes:** REQ-COL-154, REQ-COL-155, REQ-COL-156, REQ-COL-157, REQ-COL-158, REQ-COL-159
- **Depends on:** TASK-M7-56, TASK-M7-57, TASK-M7-58, TASK-M7-05
- **Needs (earlier milestones):** none
- **Reviewers:** code, qa, gui, perf, physics
- **Pitfalls:** none
- **Size:** ~800 lines, the tests and definitions included

## Goal
A payload field as a read-only `scalar` input, the same value the stain reads: its range the stain's window when the stain colours by the same field (`RANGE_AUTO` included), else the field's own `range_norm` default (R-557, RQ-478); Chart position never a field input; an absent field the node's default with "field not available at this tier". The four "Driven by the data" presets record their lab stand-in and read the real field in place of the stand-in node only (R-536): `t_end` for Relief of lifetime, the ensemble spread for Wet where chaotic, and for Unfinished where uncertain and Craquelure the fields this task defines. Three definitions (two windows, the two fields, invalid samples) and one calibration (the threshold windows) are written here under physics review.

## Acceptance tests
- `cargo test -p render print_field_input` — REQ-COL-154's verify (with the stain colouring `t_end` through a fixed window the input equals the stain's normalised `t_end` bitwise at every pixel, and under `RANGE_AUTO` it follows the stain's window; a stain that reads `t_end` only through a node other than a backbone `range_norm` does not colour by it, and the input uses lin [0, T]; with the stain not colouring `t_end` it uses lin [0, T] and is unchanged by a zoom; with the stain not colouring `ftle`, and again with it not colouring the ensemble spread, the input's window is the minimum and maximum of the valid samples over the draw and moves when the draw changes; the same draw with added samples failing `ftle_valid` (or with spreads invalid by REQ-COL-157's validity test for the spread), holding NaN or out-of-range values, gives the same window bitwise; with `ftle` absent at the tier (`has_ftle` false), and with the ensemble spread absent at E = 0 (`has_ensemble` false), the input takes the default and reports the status; with `ftle` present at the tier and some samples failing `ftle_valid`, the status is not "field not available at this tier" and those samples follow REQ-COL-157's definition; controls: an input normalised over the visible range for `t_end` changes under the zoom and fails, a fixed window for `ftle` or the spread fails the moving-draw arm, a reduction that lets an invalid sample into the minimum or maximum fails the added-samples arm, a per-sample NaN test for absence fails the present-but-invalid arm, where REQ-COL-157's validity test counts as invalid a spread a NaN test passes as valid, a spread judged by a NaN or `isnan` test in place of it fails, and otherwise `cargo xtask lint wgsl` (render contract Part 2, R-351, R-352), which fails on `isnan`, is the check that catches an `isnan` stand-in, and, where that definition counts a `footprint_undetermined` footprint invalid, a starved footprint whose finite spread is let into the measured range as a valid low value fails, a fallback to brightness fails, and `chart_position` as a field name is refused).
- Definition: §4.4 names the rule (for example the node nearest the colour slot, or the one the legend reads); the physics reviewer checks that it reads a window the stain already has and invents none (REQ-COL-155).
- Definition: §4.4 names each preset's field, a ledger field present at a stated tier, with the reason it carries the preset's meaning (uncertainty; sensitivity); the physics reviewer checks it (REQ-COL-156).
- Definition: §4.4 says what such a sample contributes to a neighbourhood operation and what its own pixel shows, and names the ensemble spread's validity test, saying with its reason whether a `footprint_undetermined` footprint counts as invalid; the physics reviewer checks that no NaN reaches a blur and that an invalid sample never reads as a valid extreme; and `cargo test -p render print_field_input` — REQ-COL-157's runtime arm (on a fixture field holding an invalid sample of each kind (a spread invalid by §4.4's test, a `sim_failed` `t_end`, an `ftle` failing `ftle_valid`, and an invalid sample of each REQ-COL-156 field), Relief's blurred height and the wash's blurred mask are finite at every pixel, the invalid sample's neighbours take the values §4.4's definition gives, and the invalid pixel does not read as the window's minimum or maximum; controls: an executor that lets the NaN into the blur fails, one that maps the invalid sample to 0 or to 1 fails, where §4.4's test counts as invalid a spread a NaN test passes as valid, one that judges the spread by a NaN or `isnan` test in place of §4.4's fails, and otherwise `cargo xtask lint wgsl` (render contract Part 2, R-351, R-352), which fails on `isnan`, is the check that catches an `isnan` stand-in, and, where §4.4 counts a `footprint_undetermined` footprint invalid, a starved footprint whose finite spread is let into the wash as a valid low value fails) (REQ-COL-157).
- Calibration: the PR proposes each window with its evidence: the physics fixtures it is measured on (named payloads, such as the slices of fixtures/slices.toml, never the lab's reference images), the tier, E and T of each, the normalisation it is calibrated under (the field's own `range_norm` default, the case where the stain does not colour by the field, REQ-COL-154), the field's measured distribution on those payloads, the share of the figure each window marks, and the share it marks when the stain colours by the field under `RANGE_AUTO`; the physics reviewer checks it; the human confirms it at the M7 gate (REQ-COL-158).
- `cargo xtask golden print-data-driven` — REQ-COL-159's verify (against the baselines in `fixtures/golden/print/` (R-146, R-110; the M8 browser suite checks the same baselines) (the reference this verify defines, rendered once and pinned there), each preset's registry entry lists its stand-in as above; the stand-in node, and only it, is replaced by a `field` node; each renders on a fixture payload within REQ-COL-142's tolerance of a reference made from the lab's graph with the stand-in replaced by the fixture's field normalised by REQ-COL-154's rule and its threshold windows set to REQ-COL-158's (R-536 D2, R-492), a mismatch beyond the tolerance accepted only where it comes from a deviation of the kinds print_graph §10 and R-492 name (screen-pixel units, frame-seeded noise) listed in the registry entry; controls: Wet with its threshold node replaced too fails the graph-shape check, a preset reading brightness when its field is present fails, a reference keeping the lab's windows where REQ-COL-158's differ is refused by the reference check, and a mismatch beyond the tolerance listed as a deviation of any other kind fails).
