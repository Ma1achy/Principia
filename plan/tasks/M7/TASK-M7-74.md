## Acceptance tests
- `cargo test -p render fragment_table_route` — on a chart with no closed-form shader code, Chart position and the presets read the backwards table in the fragment and nothing is refused; the route's answer is compared with `place` on the CPU (REQ-CHART-199). Three cases, each its own arm. (1) Outside a morph, a chart with generated forward code and no backwards formula: the fragment's route is the table as seed with Newton steps on the generated forward code (decisions.md § R-935, the bullet "RQ-767, the table route's accuracy outside a morph: (a)"). Asserted: (i) for a state on the chart's image (one decoded from a pixel), the residual in state reaches f32 rounding; the error in chart coordinates is held to `ε_res / σ_min(J)`, reported beside `σ_min(J)`; a sample whose `σ_min(J)` is below the stated floor is labelled ill-conditioned and not held to the bound; (ii) for a state off the image, the converged residual is reported as the projection distance `‖r‖_W` and never asserted against a bound; convergence is asserted by first-order optimality at its tolerance; a sample with `‖r‖_W ≤ ε_res` is binned to (i). Control: the table seed returned unrefined fails (i), or is reported void as in REQ-CHART-199's control. Arm (ii) is not read as passing until REQ-CHART-200's two definitions (the metric `W`, which nearest point) are approved. `ε_res`, the `σ_min(J)` floor and the optimality tolerance are REQ-RENDER-126's calibrations (R-71), never a value the test chooses. (2) Outside a morph, a chart with no forward code at all: the table alone; RQ-767 (a) names no criterion for it ("the table alone only where none exists"): the difference from `place` is reported and labelled, none asserted. (3) On a morph frame: R-926 item 7 applies (approximate is acceptable during a morph): the difference from `place` is reported and none is asserted (REQ-RENDER-125).
- Proposal: the proposal gives `ε_res`, the `σ_min(J)` floor and the optimality tolerance, each with its evidence; checked by the physics reviewer; confirmed by the owner; recorded in decisions.md; never a value chosen in the PR (R-71) (REQ-RENDER-126).
- `cargo xtask bench backwards_pass` — the per-sample cost of the backwards pass on Metal at 512 × 512, reported against the 16.7 ms frame budget; PASS if the pass takes at most a quarter of it; benchmark: waits for the human's Mac (R-186) (REQ-PERF-122).
