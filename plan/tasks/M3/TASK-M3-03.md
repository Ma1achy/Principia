# TASK-M3-03 — Substep control: the per-sim-key N_sub threshold table, its bucket tree and total_substeps

## Goal
`N_sub` is chosen by a generated comparison tree of the position-quantised `d²` against the sim key's f32 thresholds `THR[n] = round_f32((r_sub·n^{−1/γ_sub})²)`, generated on the host per sim key with a pinned pure-software libm, shipped as exact f32 bit patterns and read by constant index, with no runtime sqrt, div, pow, loop or dynamic index, and it equals the specification `clamp(⌈(r_sub/r_min)^{γ_sub}⌉, 1, N_max)` for every sim key (R-502). An `N_max` above the table's maximum length, a calibration value this task proposes, is refused; the default config reproduces the build-time table bit for bit. *Was:* "against 64 build-time-frozen f32 thresholds `THR[n] = round_f32((r_sub/n^{2/3})²)`". The substepper exposes the live `N_sub` per macro-step, keeps the exact `total_substeps` u32, and sets the sticky `saturated` descriptor bit iff `N_sub == N_max` occurs.

## Deliverables
- The host table generator (`crates/kernel/src/driver/nsub_table.rs`): `THR[1..=L_max]` from a sim key's `r_sub`, `gamma_sub` and `N_max`, in f64 with a pure-software libm pinned in `Cargo.lock` (no platform libm, no `std` pow), rounded once to f32 and returned as exact bit patterns for `SimUniforms`; a typed error for `N_max` above `L_max` or below 1 (REQ-INT-091).
- `cargo xtask codegen`: the comparison tree over `L_max` constant indices (no loop, no dynamic index), and the default config's table, evaluated on codegen's own build-time path through the pinned libm (not by calling the host generator's function) and checked in as `crates/kernel/src/generated/nsub_thresholds.rs`, which REQ-INT-092's test compares with the host generator (R-502; applied per R-369, qa review 5587466555 item 7 of PR #258). *Was:* "generated by the same generator and checked in"; earlier: "`xtask`/`build.rs` table generator: computes `THR[1..=64]` in f64 libm and emits only the f32 bit patterns as a generated Rust source (`crates/kernel/src/generated/nsub_thresholds.rs`) plus the comparison tree (no loop, no indexing)."
- `fixtures/gates/nsub-table/` — the fixture of configurations and their bit tables, produced independently of the generator by a checked-in reference script (`fixtures/gates/nsub-table/reference.py`: `(r_sub·n^(−1/γ_sub))²` in Python's `decimal` at 50 digits, rounded to f32 straight from the decimal value, never through `float()` and f64), each entry where the generator legitimately differs (a double rounding through f64, or the pinned libm's sub-ulp f64 error) listed with that reason; the one TASK-M8-40's wasm leg reproduces (REQ-INT-091, REQ-INT-093).
- The proposal of `L_max`, the table's maximum length, with its evidence (REQ-INT-094).
- `crates/kernel/src/driver/substep.rs` — `d2_quantised` (f32 positions, lone-sub, lone-mul, explicit `fma(dy, dy, dx*dx)`), the clamp-in-f32-before-cast rule, `bucket(d2) -> u32`, and `SubstepState { live_n_sub, total_substeps, saturated }`.
- `fixtures/gates/nsub-bucket/` — fuzzed `d²` straddling every bucket edge (±1 ulp and exact).

## Acceptance tests
- `cargo xtask gate nsub-bucket` — fuzz `d²` across and straddling every bucket edge, at the default config and at configs with `r_sub`, `gamma_sub` and `N_max` each changed (a non-power-of-two `N_max` among them): `N_sub` bit-identical on CPU-f64 and CPU-f32 (0 forks); the tree equals `clamp(⌈(r_sub/r_min)^{γ_sub}⌉, 1, N_max)` away from edges; control: the default table used under a changed `r_sub` or `gamma_sub` fails the specification check (REQ-INT-028).
- `cargo test -p kernel nsub_table_host` — the generator's bits for `fixtures/gates/nsub-table/` equal the fixture's (the reference script's correctly rounded bits, or the listed double-rounding entries); `N_max = L_max + 1` and `N_max = 0` are refused with the typed error; control: a fixture entry one ulp off fails; review: the libm is pure-software and pinned, and no `std` or platform pow is called (REQ-INT-091).
- `cargo test -p kernel nsub_default_table_bitwise` — the host generator at `r_sub = 0.05`, `γ_sub = 1.5`, `N_max = 64` reproduces the checked-in build-time table bit for bit; control: that table with one bit flipped fails (REQ-INT-092).
- Review (physics): the proposed `L_max` and its evidence (the `SimUniforms` size on every backend, the tree's size and depth, `horizon_steps × N_max ≤ 2³²−1`); the human confirms it at the M3 gate and it is recorded in decisions.md (REQ-INT-094).
- `cargo test -p kernel nsub_live_readout` — the per-macro-step `N_sub` readout equals the bucket value used for that macro-step (REQ-INT-027).
- `cargo test -p kernel saturated_sticky` — a `d²` sequence that hits the cap once then relaxes keeps `saturated = 1`; with a non-power-of-two `N_max` the flag sets exactly when `N_sub` reaches `N_max` (REQ-TOOL-033).
- `cargo test -p kernel total_substeps_proxy` — `total_substeps` is an exact u32 equal to Σ N_sub; the proxy ⌊log₂ Σ N_sub⌋ via countLeadingZeros equals ⌊log₂⌋ of the exact count at powers of two and their neighbours, and 0 for totals 0 and 1 (REQ-TOOL-034).
